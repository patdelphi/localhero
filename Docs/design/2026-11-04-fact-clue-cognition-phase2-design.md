# 第二阶段：结构化事实、核心线索与人物认知实施设计

## 1. 状态与目标

本设计已按数据边界、事务与接口、迁移与验收三部分获得确认，当前进入书面评审，尚不表示功能已经实现。

目标是在第一阶段行动管线、显式命令、事务与审计基础上，实现架构 2.1 的 A05、A06、A07：

- 让具有规则效果的线索事实和 Clock 变化具有稳定身份、来源事件和有效状态。
- 将 C01 核心线索保障与替代路径写成可检查、可测试的内容约束。
- 分离权威事件、个人观察、个人记忆、证词、调查证据和玩家假设。
- 保持现有 C01 三结局、行动预览、幂等、权限和叙事重试行为。

## 2. 已确认范围

### 2.1 本阶段完成

1. SQLite v3 结构化事实、Clock 变化、人物认知和玩家假设记录。
2. 现有案件状态继续作为快速投影，与结构化记录在同一行动事务中提交。
3. C01 必要／优势线索、获取方法和替代路径声明及可达性测试。
4. 玩家可见的知识视图和简单文本假设的新增、修改、删除。
5. v2 旧档迁移前备份、可推导快照回填和重复初始化验证。
6. 单元、事务、接口、C01 回归与真实浏览器验收。

### 2.2 明确排除

- 不接 AI Provider，不增加模型权限。
- 不实现 NPC 自主评分、长期规划、动态导演或全城模拟。
- 不实现多分支、精确回放、结构化证据连线或复杂社交关系系统。
- 不重写现有事件体系，不引入前端框架。
- 自动测试只使用临时数据库，不修改真实存档。

## 3. 总体方案

采用“结构化记录＋现有状态投影”，不扩展为全面事件溯源重写。

| 组件 | 职责 |
|---|---|
| `app/case_content.py` | C01 事实、核心线索、替代路径和固定认知内容声明 |
| `app/case_engine.py` | 有效事实判断、状态转换、核心线索内容约束和公开状态 |
| `app/action_pipeline.py` | 预览及提交前计算事实、Clock 和认知变化，保持纯计算 |
| `app/store.py` | v3 迁移、结构化记录、案件投影、假设事务和玩家知识查询 |
| `app/game.py` | 行动编排、玩家知识与假设服务，不赋予模型新权限 |
| `app/main.py` | 知识与假设 API，沿用统一异常映射 |
| `app/static/` | 证据、观察与证词、我的假设的只读／编辑展示 |
| `tests/` | 内容可达性、事务、迁移、知识权限、假设隔离和回归测试 |

权威世界事件仍由程序事务提交。人物认知和玩家假设不能反向修改权威事件，模拟模型仍只负责确定性意图解析与叙事。

## 4. 数据设计

### 4.1 结构化事实 `case_facts`

至少保存：

- `game_id`、`fact_id`、`subject_id`、`fact_kind`。
- `source_event_id`、`visibility`、`status`。
- `mechanical_json`、`invalidated_event_id`、创建时间。

C01 当前线索使用稳定 `fact_id`。只有 `status='active'` 的事实可以授予行动权限。事实失效时追加失效事件并结束有效区间，不删除事实或来源历史。

案件阶段、地点和当前 Clock 仍留在 `case_states`；当前线索列表作为有效事实的投影，不作为第二套独立授权来源。

### 4.2 Clock 变化 `clock_changes`

至少保存：

- `game_id`、`clock_id`、`source_event_id`。
- `reason`、`delta`、`before_value`、`after_value`、创建时间。
- 对游戏、Clock 和来源事件设置唯一约束，防止重复提交。

每次变化必须来自同事务的已提交事件。无来源、前后值不一致或超出本次行动声明的写入必须失败并回滚。达到显示上限不自动改变阶段或结局，只有明确收束行动可以结案。

### 4.3 人物认知 `knowledge_records`

至少保存：

- `game_id`、记录 ID、`holder_id`、`kind`。
- `source_event_id`、可选 `fact_id`、`content`、`accuracy`、`visibility`、创建时间。

`kind` 首版限定为 `observation`、`memory`、`testimony`。调查证据继续由结构化事实表达，玩家假设使用独立表，避免概念混用。

- 观察表示人物在特定条件下感知到的内容，可以不完整或误判。
- 记忆引用观察或亲历事件，衰减只改变对应记忆，不改写权威事件。
- 证词引用陈述者和来源，可以诚实、错误或说谎，不自动升级为世界真相。
- 权威事件不会自动写入所有人物知识；只按 C01 固定感知与信息传递声明生成记录。

### 4.4 玩家假设 `player_hypotheses`

保存记录 ID、`game_id`、文本、创建和修改时间。假设是可删除的玩家私人表示，不属于正典或世界历史：

- 不生成世界事件，不改变案件 `revision`，不消耗随机序号。
- 不参与行动候选、权限、Clock、线索或结局判断。
- 首版只支持文本，不支持证据连线和自动推理。

### 4.5 版本

新提交使用 `RULES_VERSION='action-pipeline-1.1'` 与 `CONTENT_VERSION='c01-1.1'`。既有行动保留原版本和审计，不改写旧记录。

## 5. C01 核心线索与认知内容

### 5.1 线索分类

为现有线索补充内容声明：

- 必要信息：没有它就无法合理到达对应结局或理解核心真相。
- 优势信息：提供额外解释、风险降低或结局选择，但不是唯一通路。
- 获取方法：产生信息的固定行动及允许的结果。
- 替代路径：原方法结果不完整时，已经创作且符合因果的后续行动。

优先复用现有结构：

- 项目导出／延迟导出均可进入共享排班。
- 完整货运签／残缺货运记录均可联系阿洛确认苗雨。
- 邵谦是否承认不是确认共享账户事实的唯一途径。
- 坏骰可以增加 Clock、暴露或额外行动代价，但不删除全部破案可能。

系统保障必要信息可达，不自动替玩家解释真相或选择结局。

### 5.2 固定认知内容

C01 只为实际行动参与者和明确信息接收者生成认知记录。例如林砚舟的就诊说明、阿洛的安全确认属于证词；玩家获得材料可以形成观察或记忆。不同人物对同一事件可以持有不同内容或准确性。

首版不生成全城人物知识，不根据主持人秘密为 NPC 建立认知，不让证词文本单独解锁超出既有事实授权的行动。

## 6. 行动流程与事务

### 6.1 预览

现有预览流程额外计算：

- 新增及失效事实。
- Clock 来源、原因、前后值。
- 将生成的观察、记忆和证词。

预览不写库、不掷骰、不消耗随机序号。声明和审计可以展示这些变化的机械摘要，但普通玩家视图不暴露未授权认知。

### 6.2 提交

沿用 `BEGIN IMMEDIATE` 和第一阶段全部复核：

1. 复核请求 ID、请求哈希、案件版本和随机序号。
2. 写入行动与 `action_committed` 事件。
3. 写入事实变化、Clock 变化和认知记录，并关联来源事件。
4. 更新案件状态投影；有案件变化时递增 `revision`。
5. 写入既有 `case_changed` 及有界后续事件。
6. 任一语句或不变量失败，整个事务回滚。

重复请求返回原行动，不重复生成结构化记录。叙事在事务外执行，重试只保存文本，不触碰事实、Clock、认知或假设。

## 7. API 与前端

### 7.1 玩家知识

新增 `GET /api/games/{game_id}/knowledge`，只返回当前玩家可见的观察、记忆和证词。普通 API 不接受任意 NPC ID 作为读取私密知识的入口。

### 7.2 玩家假设

- `POST /api/games/{game_id}/hypotheses`：新增非空文本假设。
- `PATCH /api/games/{game_id}/hypotheses/{hypothesis_id}`：修改文本。
- `DELETE /api/games/{game_id}/hypotheses/{hypothesis_id}`：删除玩家假设。

所有写操作使用独立事务；空文本返回 422，不存在返回 404，数据库异常沿用 500 映射。假设操作不调用模型，不推进游戏状态。

### 7.3 案件板

在现有案件区域增加：

- 证据：来自有效结构化事实的现有线索展示。
- 观察与证词：只读展示玩家可见认知及其来源、准确性。
- 我的假设：文本新增、编辑和删除。

继续使用原生 HTML、CSS、JavaScript。刷新后从服务端恢复，不在本地浏览器保存第二份权威状态。

## 8. v2 → v3 迁移

1. 已有存档首次升级到 v3 前使用 SQLite 在线备份生成 `.pre-v3.bak`，不覆盖已有备份；旧版升 v2 的既有保护保持有效。
2. 新表和索引在事务中创建，成功后设置 `PRAGMA user_version=3`。
3. 旧档以当前快照回填有效线索事实和 Clock 当前值，关联明确标记的 `legacy_v3_backfill` 事件。
4. 旧 Clock 只记录“迁移时快照值”，不伪造每一次历史增减。
5. 旧档已持有线索可生成 `accuracy='unknown'` 的玩家记忆，表示迁移时已知信息；不伪造具体观察、证词或秘密知识。
6. 旧行动、事件、案件 `revision` 和结局保持不变。重复初始化不得重复回填或覆盖备份。

## 9. 异常与权限边界

- 无来源 Clock、无效事实状态、非法认知类型和越权知识读取均不能产生部分写入。
- 事实失效后，对应行动立即失去权限；旧事件和审计仍保留当时有效状态。
- 错误证词、记忆衰减和玩家假设不修改权威事件或固定案件真相。
- 玩家知识接口不泄露未感知秘密；授权审计与普通玩家视图保持分离。
- 假设的新增、修改、删除失败时不改变案件状态；API 统一返回可读错误。

## 10. 验收标准

### 10.1 事实与 Clock

- 每个有效事实和 Clock 变化均可追溯到来源事件。
- 无来源或前后值不一致的 Clock 写入被拒绝并完整回滚。
- 事实失效立即撤销权限，历史不消失。
- Clock 达到显示上限不会自动结案，重复请求不会重复累计。

### 10.2 核心线索

- C01 必要信息均有至少一条已创作获取路径和失败后的合理处理。
- 固定坏骰序列下，劳动路径、生活路径和三个结局保持可达。
- 替代路径不创造新证人、新物件或新真相，获得证据不自动完成推理。

### 10.3 认知与假设

- 同一事件可产生不同人物观察；普通玩家只能读取授权视图。
- 错误证词和记忆变化不修改权威事实。
- 玩家假设增删改后，事件数、案件 `revision` 和随机序号不变。
- 空假设、跨存档修改和不存在记录均被拒绝。

### 10.4 迁移与回归

- v2 旧档迁移后当前阶段、地点、线索、Clock、结局和版本不变。
- 迁移前备份存在且不被覆盖，重复初始化不重复回填。
- 既有 33 项测试和新增测试全部通过，Python／JavaScript 语法与差异检查通过。
- 真实数据库测试前后哈希不变；浏览器完成调查、知识视图、假设编辑、刷新恢复和结案闭环。

## 11. 实施顺序

1. 先写结构化事实、Clock、核心线索、认知、假设和迁移失败测试。
2. 实现 v3 表结构、迁移、事务写入与旧档快照回填。
3. 接入 C01 内容、案件引擎、行动管线和游戏服务。
4. 实现玩家知识与假设 API 和前端案件板。
5. 运行全量回归和浏览器验收，修复后同步任务与对话记录。
