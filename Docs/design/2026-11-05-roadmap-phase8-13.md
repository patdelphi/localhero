# 《灰区事务所》后续开发路线图（第八至第十三阶段）

- 创建日期：2026-11-05
- 状态：规划中，待确认后逐阶段立项
- 依据：[当前状态](current-status.md)、[第七阶段设计](2026-11-05-ai-provider-integration-phase7-design.md)、[实施计划总表](todo.md)
- 用途：在 C01 垂直切片与在线 Provider 已跑通的基础上，规划连续可执行的后续阶段，避免每次只推进一个孤立功能。

## 1. 规划原则

- 事实先于叙事：模型只能表达已提交事实，不能决定事实、骰点、权限与结局。
- 确定性优先：所有新机制必须可回放、可审计、可关闭。
- 测试先行：每个阶段先写失败测试，再实现，最后做浏览器验收。
- 小步交付：每阶段独立可验收，不把多个大改动压在同一次提交里。
- 真实存档隔离：自动测试与浏览器验收只使用临时数据库。

## 3. 第八阶段：叙事上下文与人物口吻

### 目标

让在线叙事从“单回合扩写”变成“跨回合连贯表达”，并让不同人物有可辨认的语言差异。

### 范围

1. 叙事上下文构建器：只从已提交事实派生最近三次行动摘要、当前地点固定描述、在场人物、上一条叙事结尾与玩家已知线索提示。
2. 人物口吻档案：为方笙、唐葵、苗雨等现有 NPC 定义用词、句长、称呼与禁忌，仅用于对话与社交叙事。
3. 重复检测：对连续叙事做字符 n-gram 相似度检查，超过阈值时重试一次，仍失败则回退固定要点。
4. 上下文长度上限与裁剪规则：超长时优先保留最近行动与当前地点。

### 交付物

- 只读上下文构建模块与单元测试。
- 叙事提示词集成、口吻档案、重复检测与回退测试。
- 设计文档与状态更新。

### 验收标准

- 同一行动连续两次叙事不出现高度雷同文本。
- 隐藏真相、未公开线索与内部评分不进入提示词。
- 上下文缺失或超长时行为稳定，不影响提交与回放。
- 全量测试通过，浏览器叙事抽查通过。

### 边界

- 不让模型改变事实、判定或人物关系。
- 不引入跨场景的持久“AI 记忆”，上下文每回合重建。

## 4. 第九阶段：AI 受限情节演进

### 目标

让 AI 在固定案件框架内提出有界“情节节拍”，由程序校验后提交，而不是自由生成剧情。

### 范围

1. 定义 `DirectorProposal` 结构：节拍类型、目标行动、理由、建议效果，效果只能引用白名单。
2. 首批只开放一种节拍，例如“环境复杂化”或“NPC 主动接近”，验证通路后再扩展。
3. 触发条件：每若干行动或场景切换后最多一次，可在 `.env` 与界面关闭。
4. 校验器：拒绝新增人物、地点、线索、结局、数值与判定；限制时钟上限；同一节拍不可重复。
5. 审计扩展：记录提案、校验结果、拒绝理由与最终提交效果；回放只重放已接受提案。

### 交付物

- 提案结构、校验器、管线接入、审计 v4、界面开关与展示。
- 越权、重复、关闭开关、回放一致性测试。

### 验收标准

- 越权提案全部被拒绝，且不产生部分写入。
- 接受后的提案可确定性回放，拒绝提案不改变状态。
- 关闭功能后与第八阶段行为完全一致。
- 审计能回答“这条情节是谁提出、为何被接受”。

### 边界

- 不做自由生成剧情、多步计划、自动案件生成。
- 不突破 A 级动态权限与人工正典边界。

### 风险

复杂度最高，建议先用一个节拍类型做小范围试点，通过后再扩展。

## 5. 第十阶段：C02 与跨案关联

### 目标

交付第二宗可完整游玩的案件，并与 C01 共享人物、组织与至少一条跨案线索。

### 范围

1. 案件注册表：把 C01 固定内容迁移为可注册的案件模块，行动目录、地点、结局按案件加载。
2. C02《最后一班配送》：4—5 个地点、完整行动链、三种结局、与 C01 共享 NPC。
3. 跨案状态：一条跨案线索与一个可回收的人物关系，前端支持案件切换。
4. 存档与回放兼容：旧 C01 存档不受影响，迁移只增不改。

### 交付物

- 案件注册表与 C01 迁移、C02 内容、跨案线索、前端案件入口。
- 两案回归、迁移与浏览器闭环测试。

### 验收标准

- 新档可选择 C01 或 C02，两案均可从开场玩到结局。
- C01 全部既有测试、审计与回放保持一致。
- 跨案线索在两案中可被正确认知与引用，且不泄露隐藏真相。

### 边界

- 不在本阶段实现 C03 与全城地图。

## 6. 第十一阶段：持续 NPC 日程与城市切片

状态：已完成（2026-11-05）。实施记录见 [持续 NPC 日程与城市切片设计](2026-11-05-city-schedule-phase11-design.md)。

### 目标

让十二名持续 NPC 按日程在城市切片中活动，即使玩家不在场也会产生有界事件。

### 范围

1. 时间段、日程表与在场判定。
2. 离屏事件生成：仅在固定规则与知识视图内产生，不新增隐藏事实。
3. 人物位置面板与“今天谁在哪里”的玩家可见视图。
4. NPC 知识隔离与回放：离屏事件进入事件流但不自动进入玩家知识。
5. 性能预算：串行 SQLite 下的批量读取与写入上限。

### 交付物

- 日程模块、离屏事件、位置面板、审计与回放接入。
- 日程复现、隐私裁剪与性能测试。

### 验收标准

- 同一种子与同一存档的日程可确定性复现。
- 离屏事件不会把隐藏真相写入玩家知识视图。
- 回放校验与既有阶段一致，性能在本地可接受。

### 边界

- 不做全城持续模拟、经济系统与多城市扩展。

## 7. 第十二阶段：分支存档与推演（已完成）

### 目标

允许从任意历史行动分叉出新存档，保留原档，并支持两条分支的对比。

### 范围

1. 行动边界快照与分支元数据，SQLite v8 迁移。
2. 分支创建、命名、切换与删除策略。
3. 分支树界面与关键状态对比视图。
4. 分支回放与存储上限、清理规则。

### 交付物

- 分支存储、迁移、接口、界面与测试。

### 验收标准

- 从任意行动分叉不修改原存档，原档哈希保持不变。
- 两条分支均可独立回放并通过校验。
- 删除分支有明确确认与恢复边界。

### 边界

- 不做云端同步、多人协作与实时合并。

## 8. 第十三阶段：产品化与部署（已完成）

### 目标

把项目整理成可交付的单机版本，具备配置、备份、导出与运行观测能力。

### 范围

1. 一键启动脚本与开发／生产配置档，离线模拟模式可强制启用。
2. 存档备份、恢复与导出导入。
3. 结构化日志、模型调用耗时与回退统计、健康接口扩展。
4. 安全检查：密钥不落日志、不写入存档、健康接口只暴露公开信息。
5. 发布说明与部署文档。

### 交付物

- 启动与部署脚本、配置档、备份恢复工具、导出导入接口、发布文档。

### 验收标准

- 干净环境可启动并完成一次完整 C01 流程。
- 备份恢复演练成功，导出存档可导入。
- 日志与健康接口不含密钥；离线模式无外部调用。

### 边界

- 不做公网多租户部署、计费与运营后台。

## 9. 通用完成标准

每个阶段结束都必须满足：

- 专项测试与全量测试通过，Python／JavaScript 静态检查通过。
- 新增或变更行为有中文注释与程序说明。
- 数据库变更使用事务，SQLite 保持 WAL 与 `synchronous=NORMAL`。
- 设计文档、`current-status.md`、`todo.md` 与 `chat_history.md` 同步。
- 自动测试与浏览器验收不修改真实 `data/games.db`。
- 不自动执行 Git commit／push，需用户确认。

## 10. 建议的立即可执行项

先启动第八阶段，完成叙事上下文与口吻档案；随后用一个小范围节拍试点第九阶段。第十阶段可并行准备 C02 内容设计，但代码实施应排在第九阶段试点之后，避免同时改动案件结构与导演层。以上阶段已全部完成，路线图不再追加新阶段。
