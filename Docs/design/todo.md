# 《灰区事务所》设定圣经写作计划

## 状态记录约定

- `[x]` 表示已完成，`[ ]` 表示未完成；进行中的事项在文字后明确标注“进行中”。
- 历史完成事项只记录能够确认的日期，不补造具体时间；新事项记录创建、开始和完成时间。
- 最近状态整理：2026-11-04（架构 2.1、游戏规则优化 1.1 与研究证据总自查交付）。

## 目标

在《灰区事务所》既有游戏设计基础上，建立一套可供叙事、案件设计和后续研发共同使用的原创城市设定圣经。以大型赛博朋克作品的内容密度为参照，但不借用其世界观、组织、人物或专有设定。

## 共同边界

- 当前时间为 2060 年，采用现实技术延伸。
- 故事发生在原创国家“宁洲共和国”的沿海城市临潮市。
- 核心技术为数字身份、普及的专用 AI 与智能代理、城市算法、自动化、平台劳动、医疗与工业义体、无人设备和近海工程。
- AI 已深度参与招聘、信贷、警务、医疗、创作和生产调度；职业替代、贫富分化、算法权力、黑客产业化与责任归属是核心社会矛盾。
- 不存在记忆编辑、数字人格、意识上传、公认成熟的通用人工智能或普遍超人化改造；专用 AI 能力强大，但仍受数据、目标、接口、权限与人为操纵限制。
- 基调冷峻但有烟火气，重点关注制度、利益与普通人的生活，不把城市写成纯粹地狱。
- 所有文档互相引用统一人名、年代、地点和组织；公开事实与主持人隐秘真相分开保存。
- 本阶段只创作设定，不编程，不执行 Git 操作。

# 最小行动闭环实施计划（已确认）

## 目标与边界

依据游戏设计文档 1.0，先完成一个可运行的本地测试场景，验证“自由输入—程序判定—事实入库—模型叙事—保存读取”的最小闭环。本阶段不实现完整 C01、三宗案件、全城地图、完整人物关系网或自动案件生成。

## 已确认的技术条件

- 本阶段不调用 Strata 或任何 AI Provider，只使用确定性的本地模拟模型生成意图和叙事。
- 模拟模型与程序规则分离，测试可预测；真实模型网关不属于本阶段交付范围。
- 游戏服务只绑定 `127.0.0.1`。
- 前端采用 FastAPI 直接托管的原生 HTML、CSS、JavaScript，不引入 React 等前端框架。
- 后端使用 Python、FastAPI、Uvicorn；SQLite 使用 Python 标准库，测试所需依赖单独列出。
- 不使用 SQLAlchemy、OpenAI SDK 或其他非必要抽象。

# 参考引擎、规则与叙事系统研究计划（已确认，架构 2.1 修订完成）

计划创建：2026-11-04；最近状态整理：2026-11-04（研究证据总自查与最终复验完成）。三批对象研究、最终跨系统矩阵和架构 2.1 四阶段修订建议已完成；第 8 项总自查及最终复验完成。

## 研究目标

为《灰区事务所》动态叙事架构 2.0 提供可追溯的设计依据，回答以下问题：

1. 成熟互动叙事引擎如何组织行动校验、状态提交、文本报告和对话运行。
2. 单人跑团与戏剧导演框架如何推进动态场景、人物目标、线索线程和事件时钟。
3. 社会模拟系统如何表达 NPC 的知识、目标、关系与自主行动。
4. 现有系统如何处理故事状态保存、读取、分支、回放和内容版本。
5. 哪些机制适合融入自研轻量世界引擎，哪些会导致不必要的复杂度。

研究只形成设计依据，不直接修改游戏代码，不接入 AI Provider，不把参考项目的架构原样照搬。

## 研究原则

- 开源项目下载并固定源码与文档版本，记录仓库地址、commit、许可证和检索日期。
- 不开源或无法确认源码开放的项目，只使用公开规则书、SRD、论文、官方文档、开发者文章和公开演讲。
- 源码级结论必须引用具体文件、符号或代码路径；文档级结论必须引用 URL、章节或页码。
- 无法访问、需要付费或只有二手转述的资料明确标注证据限制，不伪装成源码研究。
- 研究第三方系统时区分“已验证事实”“作者推断”“对本项目的建议”。
- 按顺序执行，避免多个研究任务争抢模型或同时写入同一份报告。
- 第三方源码只作为本地研究快照，不直接合入项目源码或提交到 Git。

## 第一批：开源源码研究

### 1. Ink

重点研究：

- Story 的运行时状态、变量、选择、流程跳转与外部函数边界。
- 状态保存和恢复的数据结构，以及恢复后继续运行的约束。
- 作者化分支如何汇合，如何避免剧情状态完全依赖文本。
- 对本项目的用途：关键场景、人工精写内容和动态状态的表达边界。

### 2. Yarn Spinner

重点研究：

- 对话编译产物、虚拟机、指令执行和变量存储。
- 对话节点如何调用游戏逻辑，如何处理条件和选项。
- 对话状态与外部世界状态的所有权划分。
- 对本项目的用途：人物对话协议、知识视图和结构化回应。

### 3. Inform 7

重点研究：

- 人物、地点、物品、关系和属性的世界模型。
- Before、Check、Carry Out、Report 等行动处理阶段。
- 规则簿、可见性、作用域和行动失败处理。
- 对本项目的用途：行动管线、事实提交与叙事报告分离。

### 源码研究边界

- 不逐行阅读整个编译器，只追踪与上述问题有关的调用链。
- 每个项目至少形成一张核心流程、一份关键源码索引和一份可借鉴／不采用清单。
- 若实际仓库、源码结构或许可证与预期不同，先记录差异，再调整研究范围。
