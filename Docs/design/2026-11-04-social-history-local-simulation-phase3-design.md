# 《灰区事务所》第三阶段：社会状态、人物履历与局部模拟实施设计

## 1. 文档定位

- 创建日期：2026-11-04。
- 状态：设计已确认并完成实施，全量测试、浏览器验收和真实存档保护校验通过。
- 执行依据：《动态叙事架构 2.1》A08、A09、A12，以及《游戏规则系统优化稿 1.1》R05、R06、R08。
- 技术边界：继续使用 FastAPI、SQLite、原生 HTML／CSS／JavaScript 和确定性 `SimulatedModel`，不接 AI Provider。

本阶段目标是在现有行动管线和结构化事实基础上，交付社会事实最小分型、人物履历与结构状态同源、有界局部模拟，并用一条完整 C01 社交链验证其可玩性。

## 2. 范围与不变量

### 2.1 本阶段交付

1. 公开关系、方向性信任、短期社会状态和社会记忆的最小表达。
2. 人物履历与结构状态由同一事务、同一来源事件派生。
3. 固定行动的游戏内耗时、固定计划到期和短期状态结束。
4. 一条“接受委托—安抚方笙—耗时调查—收到补充证词”的完整 C01 社交链。
5. 玩家可见的人物履历、公开计划和游戏内时间，以及对应后端与浏览器回归。

### 2.2 明确排除

- NPC 自主候选评分、长期规划、欲望系统或自主决策。
- 动态导演、全城持续模拟、通用计划生成器。
- 多分支、重新推演、精确回放和结构化证据连线。
- 真实 AI Provider、联网调用和模型自动创建社会事实或计划。

### 2.3 共同不变量

- 模型只负责意图解析和已提交结果的表达，不直接修改信任、状态、计划、时间或履历。
- 公开关系不等于内心评价；A 对 B 的信任不改变 B 对 A。
- 短期状态必须有来源和结束条件，重复触发不得无限叠加。
- 履历只用于展示和回顾，权威规则判断读取结构状态，不从自然语言反推。
- 预览、叙事重试、假设编辑、页面刷新、现实时间和文本长度均不推进游戏内时间。
- 所有行动、事件、案件投影、社会状态、履历和计划在同一 `BEGIN IMMEDIATE` 事务提交或完整回滚。

## 3. 组件设计

### 3.1 `social_engine.py`

新增无数据库依赖的纯函数模块，输入固定行动声明、当前结构状态和实际判定结果，输出社会变化集。

职责：

1. 根据固定内容计算公开关系、方向性信任、短期状态、社会记忆和待建立计划。
2. 信任采用 `-2／-1／0／+1／+2`，本阶段只使用“最低提升至 +1”，不引入通用好感度。
3. 检查重复触发：同一存档的方笙安抚链只改变一次信任、建立一次社会记忆和计划。
4. 为每项变化生成可校验的结构化前后值和玩家可见性，不分配数据库事件编号。

### 3.2 `local_simulation.py`

新增无数据库依赖的纯函数模块，输入行动前后时间、当前案件范围、固定计划和当前社会状态，输出到期变化集。

职责：

1. 只处理 `scope='c01'` 且 `pending` 的固定计划，以及已经到期的短期状态。
2. 计划按 `due_time`、`plan_id` 排序，保证相同存档和行动序列得到相同结果。
3. 计划内容必须来自固定定义；前置条件不再满足时保持原计划，不伪造完成结果。
4. 无到期事项时返回空变化集，不扫描或推进其他城市实体。
5. 到期计划可产生固定证词、履历和计划完成状态，不自动产生核心事实、线索权限或结局。

### 3.3 现有模块的协作边界

- `case_content.py`：声明社交行动、固定社交结果、行动耗时和计划定义。
- `case_engine.py`：把行动耗时加入案件投影的 `world_time`；现有 Clock 仍只由 `clock_add` 推进。
- `action_pipeline.py`：生成预览摘要和实际变化集，调用两个纯函数模块，保持 Check／After 权限边界。
- `game.py`：协调真实判定、变化集和事务提交，不把调度逻辑转移给模拟模型。
- `store.py`：负责持久化、来源事件关联、声明与投影一致性校验及回滚，不承担社交评分或计划选择。
- `model.py`：继续只生成意图和叙事，不新增世界写权限。

## 4. C01 固定社交链

### 4.1 接受委托

`accept_commission` 除现有事实和认知外，新增公开关系“方笙是玩家的委托人”。关系当前状态、公开履历和来源事件一致；重复接受不重复创建关系或履历。

### 4.2 安抚方笙

新增固定行动 `reassure_fangsheng`，显示名“安抚方笙并承诺优先确认苗雨安全”。

可用条件：地点 `OC-01`、阶段 `active`、已经持有 `commission`。无需掷骰，`time_cost=1`。

首次提交产生：

1. 方笙对玩家的方向性信任最低提升至 `+1`；反向信任不变，该评价为方笙私密状态。
2. 方笙的短期状态“态度缓和”，在行动后时间开始生效，`expires_at=after_time+3`。
3. 方笙的社会记忆“玩家承诺优先确认苗雨安全”，引用本次社会变化事件。
4. 公开固定计划 `fangsheng_followup`，`due_time=after_time+2`，表示方笙整理旧排班补充。
5. 玩家可观察的回应和公开履历，但不展示方笙的精确信任值。

同一存档再次执行该行动时，只记录行动和已声明耗时，不再改变信任、短期状态、社会记忆或计划。

### 4.3 行动耗时

首版仅下列现有移动／调查行动声明 `time_cost=1`：

- `travel_hc07`、`travel_oc03`、`travel_lg05`、`travel_oc01`；
- `inspect_fangsheng_room`、`request_project_export`、`check_shared_account`、`confront_shaoqian`；
- `ask_anonymous_patient`、`check_freight_record`、`contact_miaoyu`。

新行动 `reassure_fangsheng` 同样为 1。其他未声明行动默认为 0。耗时与骰点档位无关，部分成功和局势升级的额外代价仍只使用现有内容声明，避免暗中增加双重惩罚。

### 4.4 计划到期与状态结束

示例链中，安抚后 `world_time=1`、计划到期时间为 3。随后移动和调查各耗时 1，第二次耗时行动提交后计划到期。

到期后：

1. `fangsheng_followup` 从 `pending` 变为 `completed`，保存完成事件。
2. 追加方笙的诚实证词“方笙补充了旧排班中的共享账户备注”，进入现有玩家知识视图。
3. 追加同源公开履历和局部模拟事件，不新增核心事实、不自动授予行动权限、不改变结局。
4. 短期状态只在 `world_time >= expires_at` 时结束；旧履历保留，当前投影记录结束事件。

## 5. 数据设计（SQLite v4）

### 5.1 `case_states`

新增 `world_time INTEGER NOT NULL DEFAULT 0`。`revision` 继续表示案件投影版本，任何实际 `world_time` 变化都随案件投影一并更新；无机械变化的行动不增加 `revision`。

### 5.2 `social_states`

保存当前社会结构状态，主键为 `(game_id, state_id)`。最少字段：

- `holder_id`、`target_id`、`kind`、`value_int`、`value_text`、`visibility`；
- `starts_at`、`expires_at`、`status`、`source_event_id`、`ended_event_id`；
- 创建与更新时间。

`kind` 首版限定为 `relationship／trust／condition`。信任检查值域为 -2 至 +2；短期状态必须有到期时间；来源事件非空。状态结束使用 `status='ended'` 和 `ended_event_id`，不删除当前投影或历史。

### 5.3 `character_history`

保存人物履历和社会记忆，最少字段：

- `game_id`、`holder_id`、`kind`、`content`、`structured_json`、`visibility`；
- `source_event_id`、创建时间。

`kind` 首版限定为 `relationship／trust／condition／social_memory／plan`。`structured_json` 保存可核对的前值、后值或计划状态；展示文本不参与权限判断。来源事件必须与本事务中的实际事件一致。

### 5.4 `local_plans`

保存固定计划的当前投影，主键为 `(game_id, plan_id)`。最少字段：

- `holder_id`、`scope`、`due_time`、`status`；
- `source_event_id`、`completed_event_id`、创建与更新时间。

首版状态限定为 `pending／completed`。计划定义标识就是 `plan_id`，不接收模型提供的任意效果 JSON。

### 5.5 事件与提交顺序

保留 `action_committed` 根事件，并按固定顺序追加必要事件：

1. `case_changed`：记录现有案件投影及 `world_time` 前后值。
2. `social_changed`：记录本次关系、信任、状态、记忆和计划建立。
3. `local_simulation_advanced`：记录本次实际完成的计划、结束的短期状态及产生的固定证词。

社会结构、履历、计划和知识记录分别引用对应领域事件。所有事件使用当前 `action_id`，同事务提交；没有实际变化时不创建空领域事件。

## 6. 预览、接口与前端

### 6.1 行动预览

现有 `mechanical_changes` 按判定结果增加：

- 本行动的 `time_cost` 和预计前后时间；
- 可公开的社会结果摘要；
- 可公开的固定计划建立或到期摘要。

预览不分配事件编号、不写库、不推进随机序号，不泄露私密信任或未感知计划。

### 6.2 API

- `GET /api/games/{game_id}`：案件公开状态增加 `world_time` 和玩家可见的公开计划。
- `GET /api/games/{game_id}/character-history`：只返回 `public／player` 可见履历，按来源事件顺序排列，不开放任意人物私密视图参数。
- 现有知识接口继续返回方笙到期计划产生的玩家可见证词。
- 不新增社会状态或计划的直接写 API；所有变化只能经行动提交产生。

所有 API 沿用现有异常映射，数据库写入继续使用显式事务。

### 6.3 前端

在现有案件板增加“人物与计划”区域：游戏内时间、公开计划、玩家可见履历。方笙的补充证词继续显示在“观察与证词”中。前端不保存第二份权威状态，动态文本继续使用 `textContent`。

## 7. 旧档迁移

1. v3 旧库升级前使用 SQLite 在线备份生成 `.pre-v4.bak`，不覆盖既有备份。
2. 所有旧档 `world_time` 从 0 开始，不根据现实时间或历史行动数补算。
3. 仅为当前仍持有有效 `commission` 事实的旧档回填“方笙是委托人”的公开关系快照。
4. 回填追加一次明确标记的 `legacy_v4_backfill` 事件及同源公开履历；不伪造信任、短期状态、社会记忆或固定计划。
5. 新建 v4 存档不执行旧档回填；重复初始化不得重复追加事件、关系或履历。

## 8. 异常与回退

- 未知社会类型、信任越界、缺少来源事件、错误的计划到期时间、非法可见性或履历写入失败：抛出明确异常并回滚整个行动。
- 到期计划定义不存在或声明与当前投影不一致：不提交局部结果，整个行动回滚并保留可读历史。
- 没有到期计划或状态：正常空操作，不伪造世界变化。
- 固定计划前置条件不再满足：保持 `pending`，不自动改成其他结果；本阶段固定 C01 链不设计替代计划。
- 叙事失败仍只重试叙事，不重新执行社会计算、局部模拟、掷骰或时间推进。

## 9. 测试与完成标准

### 9.1 先行测试

1. 公开关系、方向性信任、反向不变、上下限及重复安抚不叠加。
2. 私密信任不出现在玩家 API，社会记忆与结构状态引用同一来源事件。
3. 短期状态在到期前保持、达到到期时间时结束，旧履历保留。
4. 计划未到时间不前完成，到期顺序确定，完成只发生一次。
5. 预览、零耗时闲聊、假设 CRUD、叙事重试和重复请求不推进时间或计划。
6. 完整 C01 社交链产生预期证词和履历，且不增加核心事实、不改变既有三种结局条件。
7. 非法社会变化、错误到期时间或履历写入失败时，行动、事件和全部投影回滚。
8. v3 旧档备份、公开关系快照回填及重复初始化幂等。
