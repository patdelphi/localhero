# 《灰区事务所》游戏规则系统优化稿 1.1

## 阶段状态

**当前为游戏规则系统优化稿 1.1 完整建议版，三个阶段均已完成。** R01—R08 正式规则、示例和验收清单已经汇总，可作为后续规则评审与实现设计依据；游戏设计文档 1.0 原文保持不变。全程未修改游戏代码、未接入 AI Provider。

## 1. 优化依据与目标

本稿以[游戏设计文档 1.0](2026-11-03-grey-zone-agency-design.md)为规则基线，以[动态叙事架构 2.1 修订建议](2026-11-04-dynamic-narrative-architecture-2.1-research-revisions.md)为事实、权限和提交边界，并吸收[最终对照矩阵](../research/09-cross-system-final-matrix.md)中已经评审的机制取舍。

优化目标是让现有轻规则更明确、更可验证，而不是增加第二套复杂规则系统：

1. 玩家在掷骰前知道目标、方法、主要风险和预期效果。
2. 判定继续公开、轻量、可复现，不用随机替代推理或人物意志。
3. 核心线索、人物认知、关系变化、Clock 和结案分别遵守清晰规则。
4. 自由输入与行动建议继续使用同一套规则，不赋予建议隐藏特权。
5. 所有规则效果都能追溯到事件，叙事文本不创造额外机制结果。

## 2. 现有规则审查清单

| 编号 | 现有基础 | 需要补足的问题 | 优化方向 |
|---|---|---|---|
| R01 | 四类行动倾向与公开 2D6 已确定 | 掷骰前只说明修正和档位，尚未统一约定失败有多危险、成功能做到多少 | 增加轻量“处境／效果”事前声明，不增加额外骰池 |
| R02 | 使用 `2D6 + 能力修正` | 能力、状态和协助如何形成修正及上下限未明确，长期游玩容易堆叠 | 首版限制能力修正和情境修正来源，禁止同类重复叠加 |
| R03 | 核心线索已有坏骰保障与双路径要求 | 线索、证据、人物证词和玩家假设在规则上仍可能混用 | 分离信息获取、证据来源、可信程度和玩家解释 |
| R04 | 事件时钟已有来源和阈值要求 | 时钟推进、阶段变化和结案之间的关系仍需明确，避免数值自动决定结局 | 时钟只触发已定义局势变化，结案另由条件和玩家选择决定 |
| R05 | 信任、亏欠、把柄和状态标签已存在 | 信任是否双向、短期情绪与长期关系如何区分尚不清楚 | 使用方向性信任、独立债务／把柄记录和有期限状态，不设单一好感度 |
| R06 | NPC 有独立目标、恐惧和知识边界 | 社交检定可能被误解为“高分说服任何人”，回应者拒绝权不够明确 | 先判断可协商空间，再处理意图和回应；骰点不能越过人物底线 |
| R07 | 固定真相与可变结局已确定 | 案件进度积累和最终结案判定可能在未来实现中被合并 | 阶段推进、收束条件、结局选择和后果结算分别处理 |
| R08 | 判定、代价和时钟已在界面公开 | 风险与效果若不在掷骰前显示，玩家仍难以做出知情选择 | 增加事前说明、事后来源和未提交状态，不展示秘密信息 |

## 3. 明确保留的规则与范围

- 保留四类行动倾向：洞察、共情、技术、行动；不新增属性树、技能树或专长列表。
- 保留 `2D6 + 修正` 与 `10+／7—9／6-` 三档结果，不改为骰池、D20 或隐藏判定。
- 保留“无危险或没有有趣后果不掷骰”和“合理行动不重复要求无意义判定”。
- 保留固定案件真相、至少两条核心事实发现路径、坏骰不永久锁案和玩家自行推理。
- 保留信任、亏欠、把柄、状态标签、事件时钟和后果账本，不引入复杂经济、生命值或装备数值系统。
- 保留事务所固定现实压力，但本轮不重算房租、设备分期或城市经济数据。
- 保留 A 级权限、人物知识隔离、程序事务提交、事件不可变和全球正典人工批准。
- 本轮只优化规则设计，不修改 C01 固定真相、既有结局或城市世界观，也不宣称相关规则已经实现。

## 4. R01：行动声明、处境与效果

### 4.1 行动声明

需要判定的行动在掷骰前必须明确：

1. **目标**：玩家希望改变什么，而不只是使用哪个倾向。
2. **方法**：采用洞察、共情、技术或行动中的哪一种主要方式。
3. **对象与事实依据**：作用于谁或什么，当前已知条件为何允许尝试。
4. **处境**：失败或部分成功会造成多大局势代价。
5. **预期效果**：成功时合理能够改变多少。
6. **修正来源**：能力和情境修正分别来自哪里。
7. **核心信息规则**：若涉及必要线索，各档位如何保留后续可解性。

普通对话、已知地点移动、无风险查看既有材料等行动不需要完整声明，也不强行掷骰。

### 4.2 处境只决定代价严重程度

| 处境 | 适用情况 | 7—9 与 6- 的代价方向 |
|---|---|---|
| 可控 | 有准备、有退路，直接威胁较低 | 耗时、少量资源、轻微暴露或条件选择 |
| 危险 | 对方警觉、时间有限、失败会改变调查条件 | 明显暴露、关系受损、Clock 推进或失去当前优势 |
| 危急 | 正在追逐、对抗或处理重大即时危险 | 严重状态、重大局势升级或重要机会丧失，但仍不得无提示永久锁案 |

处境不再额外叠加为隐藏难度修正，避免同一困难同时降低成功率和加重后果却没有说明。处境变化必须来自已提交事实。

### 4.3 效果只决定成功能够改变多少

| 效果 | 成功时的合理范围 |
|---|---|
| 有限 | 获得局部信息、争取短暂机会、削弱障碍或完成目标的一小部分 |
| 标准 | 实现事前声明的主要目标，不产生额外重大后果 |
| 显著 | 在事实、能力和权限允许时同时改变多个直接相关条件；不能借此自动结案或修改正典 |

效果不修改骰点。难度较高的行动主要通过事实前置、有限效果或更危险处境体现，而不是不断堆高负修正。

## 5. R02：修正值与结果分档

### 5.1 首版修正规则

- 未受对应前史或内容支持的倾向修正为 `0`；首版两项背景优势倾向各为 `+1`。
- 同一行动最多应用一项有利情境修正 `+1`，来源可以是充分准备、合适工具或有效协助。
- 同一行动最多应用一项不利情境修正 `-1`，来源可以是明确状态、恶劣条件或不当方法。
- 多个同类来源不叠加，取最相关的一项；有利与不利来源可以同时存在并相互抵消。
- 首版总修正限制在 `-1` 至 `+2`。新增规则不得绕过该范围制造数值膨胀。
- 不设置由主持人随意给出的隐藏难度值；所有修正都在掷骰前公开并记录来源。

### 5.2 三档结果

| 总结果 | 机械含义 | 对核心信息的约束 |
|---|---|---|
| `10+` | 按事前声明的效果实现目标；默认没有额外暴击奖励 | 以较低或正常代价获得信息，不自动完成玩家推理 |
| `7—9` | 实现目标，同时承担事前列出的合法代价或艰难选择 | 可以获得必要信息，但不能借代价永久删除全部路径 |
| `6-` | 通常不实现预期目标，局势按声明方向升级 | 若内容规则仍给出必要信息，必须同时引入新的合法复杂化；否则保留替代路径 |

`7—9` 的代价从当前行动已声明的少量选项中选择，例如耗时、暴露、资源消耗、关系压力或降低效果；不得在结果出来后临时创造与行动无关的灾祸。

同一目标、同一方法、同一事实状态不重复掷骰“刷成功”。只有新方法、新事实或明显变化的处境才允许重新判定。

## 6. R03：线索、证据、证词与玩家假设

### 6.1 信息分型

| 类型 | 游戏规则 | 是否等于真相 |
|---|---|---|
| 核心信息 | 理解或证明核心事实所必需；案件必须提供合理替代路径 | 否，仍需玩家解释和组合 |
| 优势信息 | 降低风险、增加选择、改善结局或解释背景 | 否 |
| 调查证据 | 具有具体来源、持有者和获取事件的物件、记录或观察 | 证据可真实，解释仍可错误 |
| 人物证词 | 与具体陈述者、其知识和表达场合绑定 | 否，可能错误、隐瞒或说谎 |
| 玩家假设 | 玩家在案件板上建立的连接、排序和解释 | 否，不直接改变世界状态 |

### 6.2 获取与使用

1. 核心信息在案件内容中明确标注，不能只靠“这条看起来重要”临时认定。
2. 每条核心信息至少配置两条合理获取路径；路径可以共享部分步骤，但不能都依赖同一次骰点或同一唯一对象。
3. 坏骰可以改变获取成本、信息完整度、持有风险或后续方法，不能无提示抹除所有路径。
4. 玩家已经用合理方法直接发现答案时，不再为同一信息重复要求判定。
5. 案件板显示信息来源和玩家假设的区别，不自动替玩家连接答案，也不把“已核对”与“已证明全部解释”混为一谈。
6. 证据被公开、交出、销毁或篡改时，按事件更新其持有和公开状态；原始获取历史仍保留。

## 7. R04：事件时钟与案件结案

### 7.1 时钟推进

- 时钟通常保持少量格数，服务具体局势，不追求统一长度。
- 只有有意义的玩家行动、NPC 行动、到期计划或已提交世界事件可以推进时钟。
- 无风险的重复查看、叙事生成耗时、现实等待时间和无新事实的重复输入不推进时钟。
- 每次推进记录来源事件、原因和前后值；同一事件不能因重试或刷新重复推进。
- 时钟满值触发事先定义或经权限审核的局势变化，不直接等同于案件失败或结案。
- 时钟效果可以改变调查条件、代价和可选结局，但不得随意删除全部核心证据。

### 7.2 阶段与结案分离

案件的**世界状态**与玩家的**委托状态**分开：拒绝或未接委托不妨碍相关人物和时钟继续发展。

结案必须依次满足：

1. 玩家明确选择收束行动，例如提交复核、公开材料、私下调解、停止追查或放弃委托。
2. 程序检查该收束方式所需的事实、证据、对象和案件阶段。
3. 需要对抗或承担风险的收束行动可以判定，但骰点只决定行动代价与局势，不改写固定真相。
4. 结局按已提交事实和玩家选择生成，不由进度条满值或导演偏好自动指定。
5. 结案后分别结算公开信息、人物命运、债务、关系、事务所压力和后续回归钩子。

没有足够事实时可以尝试收束，但系统应说明证据不足或结果受限，不能把玩家假设自动当成真相。

## 8. R05：状态与方向性关系

### 8.1 状态标签

状态标签必须说明来源、影响范围和结束条件：

- 只影响标签明确关联的行动，不形成泛化数值惩罚。
- 同类状态不无限叠加；重复触发按内容规则刷新、强化或无效。
- 状态结束通过治疗、休息、兑现条件、局势变化等新事件完成，旧状态历史保留。
- 叙事者不得新增未提交标签，也不得因为文字描述缓和就提前移除标签。

### 8.2 关系规则

1. **信任**采用方向性五档 `-2／-1／0／+1／+2`，A 对 B 与 B 对 A 分别保存；界面以文字描述为主。
2. `0` 表示没有额外信任倾向，不必然表示陌生或敌对；具体共同经历仍独立存在。
3. **亏欠**是一笔笔具有来源、偿还条件和状态的债务，不合并为单一“人情分”。
4. **把柄**是具体信息、资源或承诺及其使用状态，不等于永久控制对方，也不保证对方一定屈服。
5. 短期情绪和立场使用状态标签处理，不直接改写长期信任；长期变化需要有意义的事件和回应。
6. 不设置覆盖信任、亲密、债务和矛盾的单一好感度。

## 9. R06：社交意图、回应与人物底线

社交行动按以下顺序处理：

```text
明确玩家意图与表达方式
→ 检查目标是否在场、是否理解及是否有回应能力
→ 根据目标知识、目标和底线判断是否存在可协商空间
→ 无需判定时直接回应；存在风险时公开判定
→ 目标接受、拒绝、回避、误解或提出条件
→ 按权限提交实际发生的言论、承诺、关系和状态变化
```

规则约束：

1. 高骰点不能令 NPC 放弃明确底线、相信已被其证伪的事实或泄露自己不知道的秘密。
2. 欺骗可以影响对方当下判断，但不能修改权威事实；后续发现欺骗按新事件处理。
3. 玩家说出合理论据不等于自动说服，也不等于必须掷骰；是否判定取决于目标立场、风险和实际争议。
4. 拒绝是合法回应，不必然代表行动失败；它可以揭示条件、改变策略或开启新的调查路径。
5. 威胁和把柄只改变对方的风险评估，仍须考虑其恐惧、能力和替代选择，不提供心灵控制效果。
6. 关系数值不能替代具体回应规则，也不能绕过案件或正典权限。

## 10. R07：收束规则与后果账本

每个可行收束方式在内容层面需要明确：

- 所需最低事实或证据；
- 可以参与或阻止的对象；
- 是否仍存在风险以及判定影响什么；
- 对真相公开范围、人物处境和事务所压力的影响；
- 哪些后续 Clock、承诺或案件钩子继续存在。

结局不只按“真相是否查明”分类。玩家可能查明真相但选择隐瞒，也可能只确认当事人安全便停止调查。系统分别记录：

1. 玩家实际知道和能够证明的内容；
2. 玩家选择公开、隐瞒、交出或销毁的内容；
3. 世界因此实际发生的变化；
4. 尚未解决且能够合法回归的后果。

玩家拒绝、放弃或失败不自动生成惩罚性结局；结果必须与此前事件、人物目标和现实压力一致。

## 11. R08：行动呈现与审计信息

### 11.1 掷骰前

界面以简短形式显示：

- 行动目标与主要倾向；
- 处境、预期效果和主要代价；
- 骰点修正及来源；
- 涉及核心信息时，说明失败不会永久锁案，但不泄露未知替代路径。

玩家确认前可以取消或改写行动。没有必要判定时直接执行合法结果，不展示虚假的“难度”。

### 11.2 掷骰后

界面显示骰点、修正、总结果、档位、实际效果、代价、Clock／状态变化和对应来源。未通过审核或事务失败时显示“未提交”，不用叙事成功掩盖系统失败。

### 11.3 最小审计内容

每次判定能够回溯：行动声明、处境与效果、修正来源、随机种子与结果、候选代价、权限结论、最终事件和文本版本。审计视图与普通玩家视图分离，不向玩家泄露 NPC 秘密或主持人真相。

## 12. 规则示例：带证据对质

以下只演示规则如何组合，不替换 C01 已提交内容：

- **目标**：让知情人承认共享生产账户确实存在。
- **方法**：以共情为主，出示已合法取得的项目导出。
- **处境**：危险；失败会提高对方警觉并推进项目清理。
- **效果**：标准；成功获得明确承认，不自动证明全部责任链。
- **修正**：共情背景 `+1`，有效证据准备 `+1`，总计 `+2`。
- **10+**：获得承认，不额外套取对方不知道的内幕。
- **7—9**：获得承认，但项目清理推进或对方提出保护条件。
- **6-**：本次未获得承认，对方警觉并推进清理；诊所、货运记录等既有替代路径仍可调查。
- **结案边界**：该承认可成为证据之一，但案件板中的责任解释仍由玩家形成，结案另按收束条件处理。

## 13. 阶段 2 完成边界

R01—R08 已形成正式规则，且未新增属性树、额外骰池、隐藏难度、统一好感度或自动结案条。阶段 3 将检查数值范围、档位措辞、核心线索保障、社交拒绝权、时钟与结案边界，并补充最终验收清单。

## 14. 最终验收清单

以下是后续实现与试玩需要验证的场景，不是本轮已经运行的测试：

- [ ] 普通无风险行动不掷骰；同一目标、方法和事实状态不能重复掷骰刷结果。
- [ ] 每次判定在掷骰前公开目标、倾向、处境、效果、代价方向和修正来源。
- [ ] 背景优势只提供对应倾向 `+1`，有利和不利情境各最多一项，总修正保持 `-1` 至 `+2`。
- [ ] `10+／7—9／6-` 分档与结果一致，7—9 的代价来自事前声明，6- 不被叙事改写成无代价成功。
- [ ] 处境和效果不重复转化为隐藏难度，显著效果不能自动结案或修改全球正典。
- [ ] 每条核心信息都有两条合理路径，坏骰、时钟满值和原路径失效不会无提示永久锁案。
