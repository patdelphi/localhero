## 3. 保持不变的核心边界

以下决策已经确认，本轮修补不得削弱：

1. 场景事实经程序白名单与状态校验后自动提交；案件事实经独立审核与程序校验后提交；全球正典只能由人工批准。
2. 程序协调器拥有规则、随机、权限、事务、分支头和快照的最终控制权；模型不得直接写 SQLite 或调用任意工具。
3. 导演、NPC 扮演者、审核者和叙事者使用不同上下文；NPC 不得读取主持人秘密或其他人物的私密认知。
4. 提案不等于提交，言论不等于事实，叙事文本不反向创造事实。
5. 已提交事件不可改写，纠错通过追加事件完成；原分支不会因重新推演或读档而被覆盖。
6. 精确回放不重新调用模型；重新推演始终产生新分支，不承诺模型文本逐字一致。
7. 当前阶段继续使用确定性模拟模型，不接 Strata 或其他 Provider。
8. 不引入完整 Ink／Yarn／Inform 工具链，不迁移到多 Agent 并发平台，不追求全城所有实体持续高精度模拟。

## 4. 清单中的冲突处理

| 潜在冲突 | 本建议的处理方向 |
|---|---|
| 更细的行动分层可能增加流程长度 | 分层是逻辑顺序，不要求每次行动都调用模型；无风险、无例外的行动可由程序直接完成 |
| NPC 试算与不可变事件可能冲突 | 试算只在隔离状态副本中进行，不追加正式事件；最终选择后才进入审核与提交 |
| 导演选择场景可能被误解为结果已发生 | 场景选中只代表内容单元被激活，具体行动和事实仍逐项校验 |
| 核心线索保障可能变成自动公布答案 | 只保障合理调查方法可达必要信息，不替代玩家组合证据与解释真相 |
| 历史履历双写可能产生两个权威 | 两者必须引用同一事件；结构状态用于规则，履历只用于展示，均不能独立修改 |
| 全知历史视图可能泄露主持人秘密 | 全知视图属于明确授权的管理／回放能力；普通玩家视图和 NPC 知识视图继续隔离 |
| 审计字段增加可能造成过度设计 | 只记录解释选择、复现随机和追踪事实所需的最小信息，不在本阶段展开数据库字段 |

## 5. 阶段 2 正式建议：行动与权限链

### 5.1 A01：替换标准行动流程的分层表述

**建议替换 2.0 §10 的流程说明，保留原有十步中的分支头、权限、事务和模型审计要求。**

一次需要改变世界的输入按以下逻辑阶段处理：

```text
读取分支头、正典版本与最小事实集
→ 识别输入模式、目标和行动意图
→ 前置场景例外（Before）
→ 特殊替代流程（Instead，可选）
→ 通用行动校验（Check）
→ 判定、风险、效果与费用计算（只计算，不提交）
→ 事实权限、连续性与审核级别检查
→ 再次检查分支头和请求幂等标识
→ 单事务提交主结果及有界后续反应（Carry Out + After）
→ 只读已提交结果生成叙事报告（Report）
→ 保存文本及模型调用记录
```

建议条文：

1. **Before** 只处理当前地点、人物、物品或案件状态特有的前置反应，不得跳过通用校验。
2. **Instead** 只有存在明确特殊规则时才能替代普通流程；替代结果仍须经过对应权限审核和事务提交。
3. **Check** 同时检查行动作用域、必要能力、当前事实和行动模板条件。人物可以基于错误认知尝试行动，但程序不得为让其“猜对”而泄露真实信息。
4. 无危险或麻烦的行动不强行掷骰；有风险的行动分别确定失败后果严重程度和成功能够产生的效果，不用单一难度代替两者。
5. 判定、费用和后果在提交前只是计算结果。只有经过权限检查后，费用、事实、事件、Clock 和快照才能在同一事务写入。
6. **After** 只处理由已确定结果直接触发、规则数量有界的后续反应。所有反应必须在提交前完成权限检查；需要复杂新行动的内容另起流程，禁止无限级联。
7. **Report** 不改变世界。叙事失败可独立重试，不得重新掷骰、扣费、推进 Clock 或重复提交事实。
8. 任一阶段拒绝或失败时，不伪装成剧情结果；系统保留可读历史，并返回明确的未提交状态。

**新增验收：** 非法行动不产生事件或费用；特殊替代不能越权；事务失败没有部分状态；报告重试前后世界状态一致。

### 5.2 A02：补足对话、意图、回应和宿主命令边界

**建议扩展 2.0 §6.3、§9.5 与 §10，不改变“言论不等于事实”。**

一次人物或内容运行时的回应必须区分：

| 类型 | 含义 | 是否可直接改变世界 |
|---|---|---|
| 可见表达 | 台词、动作和情绪表现 | 否；重要言论只形成言论事件 |
| 行动意图 | 发起者希望尝试的行动或社会变化 | 否 |
| 回应判断 | 目标人物接受、拒绝、回避或提出条件 | 否；只有经规则确定后才能形成结果 |
| 事实提案 | 请求新增或修改关系、认知、承诺、线索或场景状态 | 否；必须按 A 级权限处理 |
| 宿主命令 | 请求程序执行判定、移动、查询或内容跳转 | 否；由协调器验证后执行 |
| 叙事报告 | 对已提交结果的文学表达 | 否 |

建议条文：

1. 发起者的 intent 不等于结果，回应者必须能基于自己的目标、知识和关系独立拒绝或提出条件。
2. 普通寒暄不强制进入行动判定；承诺、威胁、透露信息或关系变化是否提交，由规则和权限决定，而不是由台词语气决定。
3. 内容运行时的只读查询与副作用命令必须分开。任何可能写数据库、扣费、推进时间或追加事件的命令都不得标记为可前瞻执行。
4. 所有副作用命令都经过程序协调器，并使用请求幂等标识。预览、前瞻、候选比较和叙事重试不得执行真实副作用。
5. 无法解释的玩家输入或非法宿主命令进入明确回退，不由叙事者补写一个看似合理的结果。

**新增验收：** 同一命令重复到达不会重复提交；回应者拒绝不会被发起者高分覆盖；NPC 台词不会自动成为事实。

### 5.3 A03：增加 NPC 合法候选与安全试算

**建议扩展 2.0 §9.1、§9.2 与 §10，采用短期、可解释、串行的自主决策，不引入长期规划器。**

NPC 或导演需要选择行动时，按以下顺序处理：

```text
读取该人物的知识、目标、关系和当前作用域
→ 过滤当前合法行动候选
→ 在隔离状态副本中试算候选后果
→ 按人物偏好和可解释规则评分
→ 选择候选并形成行动意图
→ 回应者判断及 A 级权限审核
→ 进入标准行动提交流程
```

建议条文：

1. 候选生成只使用该人物有权知道的信息。世界真相用于程序校验时，不得反向泄露到人物评分理由或台词中。
2. 人物评价采用少量稳定目标、现实压力、关系和当前状态，不追求长期最优，不通过大规模 desire 堆叠制造“智能”。
3. 试算必须是无副作用操作：不写数据库、不追加正式事件、不调用外部工具、不消耗正式随机序列，也不改变原分支头。
4. 候选分数只用于选择，不代表行动合法、对方接受或结果已经发生。高分不能越过 Check、回应者判断和 A 级权限。
5. 无合法候选时，人物可以等待、观察、维持原计划或给出可理解的回退行为；不得强行创造不适配行动。
6. 多个候选并列时，可使用可复现随机选择，并保存候选集与随机信息。

**新增验收：** 试算前后权威状态和随机序列不变；NPC 不能依据未知秘密评分；无候选流程能够安全结束。

### 5.4 A04：限制场景导演为合法候选排序者

**建议扩展 2.0 §9.1，并与 §8 的权限分级连接。**

场景导演的标准职责调整为：

1. 根据当前情境、时钟、人物目标和已有内容触发条件提出场景单元。
2. 从内容库中过滤前置条件不满足、参与角色不适配、当前分支不可用或权限级别不允许的候选。
3. 对合法候选按明确的作者优先级、近期状态和可复现随机信息排序或选择。
4. 激活场景单元后，再分别处理其中的人物行动、玩家输入和事实提案。

建议条文：

- 场景被选中只表示内容单元开始，不表示其中预设结果已经全部发生。
- 必填角色、必要关系或前置事实不满足时，该场景不得“绿灯”；系统应选择其他合法内容或回退。
- 导演不得直接指定骰点、覆盖回应者判断、提交案件真相或修改全球正典。
- 无合法候选时保持当前场景、推进已有合法计划或返回可解释的等待状态；不得以“保持戏剧性”为理由强行生成事实。
- Mythic 仅作为职责分层参考；在没有完整规则证据时，不声称实现其场景阈值、Chaos 或 List 算法。

**新增验收：** 角色不适配的场景不会上演；导演无法越权提交；无候选回退不改变世界事实。

### 5.5 A05：统一结构化事实、Clock 与进度规则

**建议扩展 2.0 §7、§10 与 §12，保留 SQLite 为运行时事务权威。**

具有规则效果的事实不能只有自然语言描述，至少需要在概念上区分：

- 稳定身份与附着对象；
- 来源事件和所属分支；
- 公开范围、知识可见范围与审核级别；
- 当前状态、生效条件和失效条件；
- 对行动权限的限制或授予；
- 与叙事表达分离的机械效果。

建议条文：

1. 结构化事实即使未被主动引用，也在有效期间持续约束行动；自然语言 Aspect 或履历文本不能单独承担该职责。
2. 事实被合理移除或替换时，通过新事件结束其有效区间，不删除旧历史。
3. Clock、目标进度和关系数值只能响应具有事实依据的已提交事件。每次变化记录来源、原因、前后值和所属分支。
4. 无危险、无进展或无实际障碍时，不为了节奏强行推进 Clock；现实时间流逝本身不构成充分理由。
5. 进度积累与结局判定分开。只有明确的收束行动或结局条件成立时，才判断目标完成、部分完成或失败。
6. 数值本身不得创造超出人物能力、行动效果或权限级别的结果；结案、人物命运和案件真相仍按对应审核级别处理。

**新增验收：** 没有来源事件的进度变化被拒绝；失效事实不再授予行动权限；进度积累不会自动触发结案。

### 5.6 A11：扩展选择与随机审计

**建议扩展 2.0 §12.2、§12.4 与 §13.3，审计范围同时覆盖程序规则和模型角色。**

对于影响世界发展的候选选择，应能追溯：

1. 输入情境、候选集及候选被排除的理由。
2. 适用行动、场景或社会规则及其版本。
3. 试算是否发生、评分摘要和最终选中理由。
4. 随机种子、随机结果及其所属分支。
5. 正典版本、内容版本、规则版本和相关模型调用。
6. 审核结论、最终提交事件及未提交原因。

建议条文：

- 精确回放直接读取当时保存的候选选择和随机结果，不重新评分或抽样。
- 重新推演可以重新计算，但始终进入新分支，并保留新一次的候选和版本信息。
- 审计记录可以包含主持人秘密，但只能出现在授权审计视图；普通玩家界面不得因此获得秘密。
- 审计以解释选择和复现过程所需的最小信息为限，不要求保存每次试算的全部文学文本。

**新增验收：** 任一重要选择都能回答“有哪些候选、为何排除、为何选中、使用什么随机与版本、最终提交了哪个事件”。

## 6. 阶段 2 校验结论与下一阶段入口

阶段 2 已形成 A01—A05、A11 的正式建议条文，并满足以下边界：

- 场景候选、行动意图、回应、试算、审核、事实提交和叙事报告彼此分离。
- 任一候选评分、外部函数或宿主命令都不能直接产生正式世界变化。
- Clock、结构化事实和模型／程序选择均能追溯到来源与版本。
- A 级权限、程序最终提交权和现有多分支边界保持不变。

阶段 3 将处理 A06—A10、A12，形成调查、认知、社会状态、历史视图和局部世界推进的正式建议条文。阶段 2 的内容仍需与阶段 3 一起进行最终一致性校验，当前不标记研究计划第 7 项完成。

## 7. 阶段 3 正式建议：调查与历史链

### 7.1 A06：增加核心线索保障与合理替代路径

**建议扩展 2.0 §7、§8 与 §10，把案件可解性从目标变成可验收约束。**

案件内容在概念上需要区分：

- **必要信息**：没有它就无法合理理解或证明核心真相。
- **优势信息**：提供额外解释、谈判筹码、风险降低或结局选择，但不是唯一通路。
- **调查方法**：观察、询问、检索、比对、潜入或其他符合当前情境的行动。
- **玩家解释**：玩家对证据关系的判断，不由系统自动宣布为真相。

建议条文：

1. 核心线索不得因单次坏骰永久消失。自动获得、检定获得或花费获得是不同内容选择，但必要信息必须保留符合因果的可达路径。
2. 失败可以带来时间、风险、关系、暴露或额外行动代价，也可以暂时封闭原方法；不得无说明地删除全部破案可能。
3. 原路径因玩家行动或世界变化失效时，系统从已创作、已授权的替代方法中选择；需要改变案件真相或全球正典的“补救”不予自动提交。
4. 获得证据与理解真相分离。系统可以保障玩家获得必要信息，但不能替玩家自动完成推理、选择指控对象或决定结案。
5. 替代路径必须沿用现有事实和人物能力，不为救场临时创造不合因果的证人、物件或秘密。
6. 不直接照搬 GUMSHOE 的全部花费与技能体系；本项目只吸收必要信息保障和非单线调查网络原则。

**新增验收：** 每个案件骨架都能列出必要信息、至少一条合理获取路径及原路径失效后的处理；坏骰测试不会无提示地永久锁死核心案件。

### 7.2 A07：分离世界真相、观察、记忆、证词和玩家假设

**建议扩展 2.0 §7 与 §15，将“人物认知”拆成具有不同权威和可见范围的概念类型。**

| 类型 | 权威与来源 | 允许的错误或变化 | 默认可见范围 |
|---|---|---|---|
| 权威世界事件 | 经对应权限审核并由程序提交 | 只能追加纠错，不能原地改写 | 全知授权视图；玩家只见其可感知部分 |
| 个人观察 | 某人物在特定条件下感知到的事件或状态 | 可能不完整、误判或形成假阳性 | 观察者及获授权者 |
| 个人记忆 | 对观察或亲历事件的持续记录 | 可衰减，时间和细节精度可下降 | 记忆持有者及获授权者 |
| 证词 | 某人物对观察、记忆或主张的表达 | 可以诚实、错误、隐瞒或说谎 | 听到证词者及获授权者 |
| 玩家假设 | 玩家在证据板上建立的连接和解释 | 可随时修改，不具有世界事实权威 | 玩家 |
| 调查证据 | 对权威事件、物件、观察或证词的引用 | 证据真实不自动等于解释正确 | 按案件和持有者确定 |

建议条文：

1. 权威事件不会自动写入所有人物知识。只有满足感知条件或通过合法信息传递，才生成对应观察或记忆。
2. 位置异常、最后在场、持有物品等可以支持怀疑，但不能单独证明实际行为；不同调查结论必须能保留假阳性。
3. 证词引用其来源和陈述者，不因被记录就升级为权威事实；说谎也需区分人物真实知识与其表达内容。
4. 玩家假设和证据板连接不参与权威世界状态判定，直到通过后续行动取得新证据或完成对应审核。
5. 人物行动评分只能读取其知识与记忆；导演和审核者使用更完整上下文时，不得把秘密复制到人物上下文。
6. 记忆衰减只影响对应人物的回忆精度，不改写原权威事件，也不影响其他人物的独立记忆。

**新增验收：** 同一事件可产生不同人物观察；错误证词不会改变真相；玩家错误假设不会反向修改案件；角色视图不泄露未感知秘密。

### 7.3 A08：对社会事实进行最小分型

**建议扩展 2.0 §6、§7 与 §15，避免把所有社交变化都压成统一关系数值。**

| 类型 | 例子 | 主要规则边界 |
|---|---|---|
| 公开关系事实 | 亲属、雇佣、债务、正式承诺 | 需要来源事件；按场景、案件或正典权限提交 |
| 方向性评价 | A 信任 B、A 对 B 有好感、A 认为 B 不可靠 | A 对 B 与 B 对 A 分开；默认属于评价持有者的私密状态 |
| 短期社会状态 | 被激怒、尴尬、受到吸引、正在回避 | 必须有触发来源和结束或衰减条件 |
| 社会记忆 | 记得某次帮助、羞辱、失约或共同经历 | 从持有者视角记录，引用来源事件，不等于双方共享同一解释 |

建议条文：

1. 关系变化先形成行动意图和回应判断，再按权限提交结果；意图与表演不得直接改数值。
2. 公开关系事实不等于双方内心评价，方向性评价也不自动成为公开信息。
3. 短期状态不能无期限残留，也不能在每次对话后无条件叠加；重复触发按规则刷新、增强或无效。
4. 社会记忆用于后续回应和人物履历，但只有结构化状态参与规则判断，文学描述不直接提供数值效果。
5. 全局身份、长期正典关系和重要人物命运仍按全球正典或案件事实权限处理，普通场景导演不得自动修改。

**新增验收：** A 信任 B 不会同时令 B 信任 A；私密评价不会出现在无权限视图；短期状态能按条件结束；台词不会绕过回应与审核。

### 7.4 A09：人物履历与结构状态必须由同一事件派生

**建议扩展 2.0 §12 与 §15，防止长期游玩后出现“履历说发生过、规则却查不到”的分裂。**

建议条文：

1. 一次世界变化在事务内提交权威事件，并由同一事件生成人物履历和可查询结构状态。两者保存相同来源事件标识。
2. 履历负责可读展示和回顾，结构状态负责行动校验、人物选择、关系与时钟规则；二者不得分别接受独立写入。
3. 展示文本需要重写或润色时，不改变结构状态，也不重新提交原事件；文本版本可以独立记录。
4. 结构状态失效或被替换时保留旧履历，通过新事件追加变化，不删除曾经发生的历史。
5. 需要重建当前状态时，以事件和明确的派生规则计算；不能以履历自然语言反向推断权威结构状态。
6. 任一写入失败则整个事务回滚，不允许只保留履历或只保留数值变化。

**新增验收：** 重要人物变化均能由履历追溯到事件，再由事件核对结构状态；报告重写和读取旧档不会改变人物事实。

### 7.5 A10：明确历史视图、导出与确定性回放的边界

**建议扩展 2.0 §13 与 §14，保留原有三层存档模型。**

系统需要提供四种不同能力，不得互相冒充：

| 能力 | 读取内容 | 不承诺的能力 |
|---|---|---|
| 全知历史视图 | 授权范围内的事件、人物变化、时钟和来源 | 不等于角色都知道，也不自动等于完整逐帧重演 |
| 角色知识视图 | 该角色的观察、记忆、证词和已知事实 | 不包含未感知世界真相或其他人物私密认知 |
| 历史查询／导出 | 按权限筛选的事件和状态表示 | 不承诺无损快照、完整字段或可直接恢复运行 |
| 确定性精确回放 | 已保存事件、候选选择、随机结果、内容版本和文本 | 不重新调用模型，不重新评分或抽样 |

建议条文：

1. 普通玩家历史界面按玩家知识过滤；主持人或开发者全知视图属于明确授权能力，并醒目标识其信息范围。
2. 导出文件只是特定视图在特定版本的表示。字段不完整时必须提示，不能据此宣称可以精确恢复分支。
3. 精确回放从保存记录重建过程；缺少必要版本或随机信息时明确降级为历史查看，不伪造“精确”。
4. 重新推演读取指定输入并重新计算，始终创建新分支；不得覆盖原分支或将新结果写回旧历史。
5. 叙事文本回放使用当时保存版本。润色旧文本属于新表示，不改变已提交事件和当时事实。

**新增验收：** 角色视图无法读取秘密；不完整导出被明确标注；精确回放不发起模型调用；重新推演后原分支头保持不变。

### 7.6 A12：将世界推进限制为有界局部模拟

**建议扩展 2.0 §9.6 与 §16，维持本地串行和程序优先级。**

每次需要世界反应时，只处理：

- 当前场景和当前地点的直接参与者；
- 当前案件关联人物、物件和 Clock；
- 已经存在的 NPC 计划、约会、承诺和到期事件；
- 与玩家行动有直接因果关系的邻近状态。

建议条文：

1. 城市背景采用预设日程、作者化计划和少量有依据的偏离，不在每个玩家回合推进全城所有实体。
2. 屏幕外事实不会因未被玩家观察而停止存在；但系统只在相关事件到期或行动影响范围内计算必要变化。
3. 局部偏离必须由行动、时钟或已提交事实触发；无事实依据时不随机改写人物位置、物件归属或案件真相。
4. 无合法候选、计算超时或规则失败时，保持原计划、等待或返回明确回退，不伪造一个已经完成的世界结果。
5. 模型只参与其角色负责的评价、提案和表达；所有世界推进仍经程序协调器串行处理。
6. 现实时间、模型生成耗时或叙事长度本身不自动推进游戏 Clock，只有符合规则的游戏内事件才能推进。

**新增验收：** 无意义闲聊不会引发全城重算；屏幕外计划能按来源事件恢复；局部计算失败不提交半成品状态。

## 8. 阶段 3 校验结论与最终汇总范围

阶段 3 已形成 A06—A10、A12 的正式建议条文，并满足以下边界：

- 核心线索保障不等于自动公布答案，调查失败仍有明确代价和因果约束。
- 世界真相、观察、记忆、证词、调查证据和玩家假设不再互相自动提升。
- 人物履历和结构状态具有共同事件来源，历史查看、角色知识和确定性回放分别验收。
- 世界推进只计算与当前游戏相关的局部事实，不引入全城持续高精度模拟。

阶段 4 将检查十二项条文之间的术语、权限、事务、知识和回放边界，补齐总体验收清单，并在通过后同步研究索引、todo 与对话历史。全部外部引文和链接的总自查仍属于研究计划第 8 项，不在本阶段提前执行。

## 9. 阶段 4 汇总：统一不变量与总体验收

### 9.1 十二项修订共同遵守的不变量

1. **提案与提交分离。** 场景选择、NPC 评分、AI 提案、回应者判断和宿主命令都不能自行成为世界事实。
2. **权限不被便利性覆盖。** 核心线索保障、戏剧节奏、人物高分、异常恢复和内容回退均不能绕过 A 级权限。
3. **世界真相与认知分离。** 程序可以校验真实状态，但人物只能依据自己的观察、记忆、证词和已知事实行动。
4. **事务与叙事分离。** 所有世界写入在程序事务内完成；Report、润色、导出和历史查看均不反向提交事实。
5. **试算与正式执行分离。** 试算不改变权威状态、分支头、事件日志或正式随机序列。
6. **来源与版本可追溯。** 结构化事实、Clock、履历、候选选择和随机结果均能回到来源事件及相应版本。
7. **历史不可被新表示篡改。** 纠错和状态失效追加新事件；回放、重述、导出和重新推演不改写旧分支。
8. **计算范围有界。** 不引入全城持续模拟、长期规划器、大规模欲望堆叠或不受控的多 Agent 并发。

### 9.2 总体验收清单

后续实现设计或编码至少应覆盖以下验收场景；本清单不是本轮已经运行的测试：

- [ ] 无风险普通行动不掷骰，非法行动和无权限提案不产生正式事件、费用或 Clock 变化。
- [ ] Instead、After 和后续反应不能绕过通用权限；任一事务失败时没有部分写入。
- [ ] 叙事失败重试、只读前瞻、宿主命令重放和页面刷新不会重复提交事实。
- [ ] NPC 试算前后权威状态与随机序列一致，NPC 不因读取主持人秘密而获得更高评分。
- [ ] 发起者提出社交意图后，回应者能够拒绝；场景角色不适配或无候选时能够安全回退。
- [ ] Clock 与结构化事实具有来源事件；失效事实不再授予权限，进度积累不自动完成结局。
- [ ] 核心线索不会无提示地因单次坏骰永久消失，替代路径不创造不合因果的新真相。
- [ ] 错误观察、记忆衰减、谎言和玩家假设均不会修改权威世界事件。
- [ ] 公开关系、方向性评价、短期状态和社会记忆按各自权限与生命周期处理。
- [ ] 人物履历与结构状态可由同一来源事件核对，文本润色不改变人物事实。
- [ ] 角色知识视图不泄露秘密，不完整导出被标注，精确回放不重新调用模型。
- [ ] 重新推演只创建新分支，原分支和旧事件保持不变；局部计算失败不提交半成品世界状态。

### 9.3 建议采用顺序

若后续评审决定实现，建议按依赖关系分步采用，而不是一次性扩展：

1. 先统一行动提交、宿主命令、事务幂等和审计边界。
2. 再补结构化事实、Clock、核心线索及认知分型，保证案件与人物知识可靠。
3. 然后增加 NPC 候选试算、场景候选和社会状态，避免在事实基础不稳时扩大自主性。
4. 最后完善履历、历史视图、导出和回放界面，并用多分支场景做端到端验收。

这只是架构采用顺序，不是实施计划，也不授权修改代码。游戏规则系统的具体数值、行动列表和内容模板应在独立优化文档中处理，不与本架构建议混写。

### 9.4 最终自审

- A01—A12 均有清单条目和正式建议条文，未留下空白占位项。
- 行动、权限、事务、知识、历史和分支术语已统一，未把上游机制描述为本项目已实现功能。
- 所有项目本地证据链接均指向既有研究或设计文档；第 8 项总自查及最终复验已完成，保留限制不削弱 A01—A12 边界。
- 建议未要求引入完整上游引擎、新 Provider、数据库迁移或代码实现，范围保持在架构修订。
