# 第六阶段：人物认知误差、记忆衰减与追加纠正实施设计

## 1. 文档定位

- 创建日期：2026-11-05。
- 状态：已实施并完成验收（2026-11-05）。
- 执行依据：《动态叙事架构 2.1》A02、A03、A07、A10、A11，以及《游戏规则系统优化稿 1.1》R05、R06。
- 技术边界：继续使用 FastAPI、SQLite、原生 HTML／CSS／JavaScript 和确定性 `SimulatedModel`，不接 AI Provider。

本阶段目标是在现有结构化认知、NPC 自主决策和确定性回放之上，交付有来源的人物观察、诚实误判、个体记忆衰减和追加纠正。只扩展 C01 既有方笙委托细节与补充排班链，不新增案件、正式 NPC、核心线索、行动权限或结局。

## 2. 已确认假设与范围

### 2.1 已确认假设

1. 第六阶段主题为“认知误差与记忆衰减”，不包含 NPC 主动说谎或隐瞒。
2. 错误证词来自不完整观察、过度推断或记忆精度下降；`accuracy='honest'` 只表示诚实表达，不保证内容正确。
3. 采用 SQLite v6，扩展 `knowledge_records`，不另建第二套认知事件日志。
4. 记忆衰减只依赖游戏内时间、观察时间和固定规则，不使用现实时间、模型或新随机数。
5. 正常新档方笙链仍在世界时间 3 选择 `share_schedule`，既有共享账户补充证词不变。
6. 自动测试、迁移测试和浏览器验收只使用临时数据库，不修改真实 `data/games.db`。

### 2.2 本阶段交付

1. 观察、记忆、证词之间的显式来源关系及同 holder 纠正关系。
2. 可确定的记忆有效精度、证词发言时精度和旧记录不 retroactive 改写的规则。
3. 方笙“最后登录→错误独占使用推断→补充排班时纠正”的固定可玩链。
4. 记忆精度参与 NPC 候选合法性、评分和安全回退。
5. SQLite v6 备份迁移、版本 3 审计、玩家认知裁剪和前端纠正展示。
6. 认知来源、精度、误判和纠正关系的确定性回放及篡改检测。

### 2.3 明确排除

- 主动说谎、欺骗动机、秘密目标、隐瞒评分或通用社会推理。
- 新行动、新核心线索、新结局、新案件或新增正式 NPC。
- 信任、公开关系和社会记忆的通用衰减；本阶段只处理 `knowledge_records` 中的观察与记忆。
- 自由文本认知来源、模型生成误判、动态感知系统或全知 NPC 自动同步事实。
- 多分支、重新推演、无损导出和真实 AI Provider。

### 2.4 共同不变量

- 权威世界事件、`case_facts`、玩家观察和人物记忆保持分离；认知记录不能反向提升为权威事实。
- 玩家假设不参与 NPC 知识、记忆精度、候选评分、纠正或案件权限判断。
- 世界事实不会仅因公开或玩家已知就自动成为 NPC 的精确知识，仍须固定感知或信息传递声明。
- 衰减只改变某 holder 当前记忆的有效精度，不改原观察、原记忆内容、其他 holder 记忆或既有证词。
- 纠正通过追加记录完成，不原地修改旧观察、旧记忆或旧证词正文。
- 认知试算、预览和回放不写原档、不追加事件、不增加 revision、不消耗随机序号。

## 3. 方案取舍

### 3.1 采用：扩展现有认知表与纯函数精度视图

在 `knowledge_records` 增加来源、观察时间、基础精度和纠正引用。新记忆由观察或既有记忆生成，新证词引用其表达来源；有效精度由纯函数按当前游戏内时间计算。

该方案保留第二阶段表、第三阶段来源事件、第五阶段 NPC 知识视图和第四阶段回放投影，改动集中在既有边界内。数据库保存稳定事实，时间相关衰减按需推导，避免每个行动批量更新记忆行。

### 3.2 不采用：不迁移、按固定内容隐式推导

只根据 `source_event_id` 和内容定义推断来源与年龄，虽然不改表，却无法可靠表达“某证词来自哪条记忆”“哪条记录纠正哪条误判”。纠正与回放会依赖文本匹配或隐藏规则，审计边界不清晰。

### 3.3 不采用：独立 append-only 认知事件日志

另建完整认知事件表并重算当前视图可覆盖更复杂认知系统，但会与 `knowledge_records` 形成双状态来源，增加迁移、查询和回放成本。当前 C01 只需要一条固定误判链，不采用该通用化方案。

## 4. 认知数据契约

### 4.1 v6 新增字段

`knowledge_records` 保留现有字段，并增加：

| 字段 | 类型与空值 | 含义 |
| --- | --- | --- |
| `source_record_id` | `TEXT NULL`，自引用 | 新记忆或证词的直接认知来源；外部观察可为空 |
| `observed_at` | `INTEGER NULL` | 新观察或记忆形成时的游戏内时间；证词和旧迁移记录可为空 |
| `precision` | `TEXT NOT NULL` | `exact／vague／fragmentary／unknown`，保存基础精度或证词发言时精度 |
| `corrects_record_id` | `TEXT NULL`，自引用 | 本记录追加纠正的先前认知，不修改目标正文 |

新增 `(game_id, source_record_id)` 和 `(game_id, corrects_record_id)` 索引。数据库约束与服务层共同保证来源和目标存在；服务层还必须校验同 `game_id`、合法 holder、事件顺序和无环。

### 4.2 来源图规则

1. 外部观察的 `source_record_id` 为空，`source_event_id` 指向触发感知的既有事件。
2. 新记忆必须引用同 holder 的观察或记忆；后者只用于固定的个人解释或重新整理，不允许跨 holder 复制秘密。
3. 新证词必须引用同 holder 的观察或记忆；旧版无来源证词按 `unknown` 保留，不伪造来源。
4. `corrects_record_id` 必须指向同 game、同 holder、更早事件中的记录，禁止自指、跨档、跨 holder 和成环。
5. 一个来源可产生多条记忆或证词；每条纠正记录只追加一个纠正关系，不删除旧记录。
6. `fact_id=NULL` 不表示内容必然错误，只表示该认知没有获得权威案件事实地位；错误推断不得写入 `case_facts`。

### 4.3 `accuracy` 与 `precision` 分工

- `accuracy` 延续现有来源／表达属性：`direct`、`honest`、`misleading`、`unknown`。
- `precision` 只描述细节完整程度，不证明内容真假，也不表示陈述者是否诚实。
- 诚实证词可以引用错误观察或过度推断；直接观察也可能不完整。
- 玩家界面不得把 `honest` 显示为“内容真实”，统一显示为“诚实陈述”。
- 内部错误标记、秘密来源和私有记忆正文不得通过公开精度字段泄露。

## 5. 记忆衰减与纠正规则

### 5.1 有效精度

对 `observation／memory`，在指定 `world_time` 计算：

| 距 `observed_at` 的时间 | 有效精度上限 |
| --- | --- |
| 0—3 | 保持基础精度 |
| 4—6 | 最高为 `vague` |
| 7 及以上 | `fragmentary` |

规则如下：

1. 基础 `exact` 可在 4—6 点降为 `vague`，在 7 点及以上降为 `fragmentary`。
2. 基础 `vague` 不会回升为 `exact`，在 7 点及以上降为 `fragmentary`。
3. 基础 `fragmentary` 不随时间回升；合法枚举值 `unknown` 始终保持 `unknown`，不满足任何最低精度要求。
4. `observed_at > world_time`、负观察时间或枚举外精度属于数据错误，明确失败，不静默按精确处理。观察与记忆必须有 `observed_at`；唯一例外是 v5 迁移且 `precision='unknown'` 的旧记录。
5. `testimony` 保存发言时的有效精度，之后不随源记忆继续衰减。
6. 新观察可以生成新的较清晰记忆，但不能修改旧记忆或旧证词；C01 不新增专门的回忆恢复行动。

有效精度是纯函数结果，不生成批量衰减事件，不增加 revision，也不写数据库。

### 5.2 追加纠正

纠正记录必须引用固定内容声明中的 `correction_id`、来源记录和被纠正记录；`correction_id` 是声明标识，不新增数据库字段。提交前依次检查：

1. 当前 holder 是否通过合法观察或信息传递获得纠正依据。
2. 被纠正记录是否属于同一 holder 且早于当前行动。
3. 纠正内容是否只收窄或撤回原认知，不提交新的未授权事实。
4. 公开纠正是否只引用玩家原本可见的证词；私有记忆被纠正时不生成公开提示。

若没有先前的公开误判证词，仍可追加方笙自己的记忆纠正，但不补造“玩家曾听过误判”的历史。

## 6. 组件与职责

### 6.1 新增 `cognition_engine.py`

使用无数据库依赖的纯函数，建议接口：

```python
def effective_precision(record, world_time):
    """返回指定游戏内时间的记忆精度，不修改输入。"""


def build_cognition_view(holder_id, records, world_time):
    """只建立指定 holder 的来源视图、有效精度和纠正投影。"""


def build_declared_cognition(action, outcome, context, after_time):
    """按固定声明生成观察、记忆、证词与追加纠正。"""


def validate_cognition_changes(changes, context, source_event_order):
    """校验来源、权限、时间、精度、纠正目标和有界数量。"""
```

所有输入深拷贝后使用；函数不得调用 `GameService.act`、数据库写接口、模型或随机数。

### 6.2 `npc_decision.py`

- `build_npc_knowledge` 返回带来源和有效精度的 holder 视图，不再只返回无精度引用集合。
- `make_decision_context` 纳入四个 v6 字段和当前 `world_time`，继续排除物理时间戳、玩家假设和他人私密知识。
- 候选知识条件支持 `knowledge_id` 与 `min_precision`，评分只读取当前 holder 的有效视图。
- 原始 `public_facts` 不直接赋予 NPC 精确记忆；只有固定感知或信息传递声明生成的记录参与最低精度判断。
- 候选试算校验固定认知产物及纠正目标，拒绝任意正文、跨 holder 来源或未声明 `fact_id`。

### 6.3 现有模块协作

- `case_content.py`：声明方笙初始观察、记忆、误判、各精度公开文本、最低知识精度和固定纠正；版本升级为 `c01-1.3`。
- `action_pipeline.py`：在行动后时间边界生成固定认知变化，再执行回应者、NPC 决策和导演；审计升级为 v3。
- `store.py`：完成 v6 迁移、新档初始认知、来源校验、同事务写入和玩家视图裁剪。
- `game.py`：继续使用唯一 `act→commit_action` 提交入口，不增加认知直写 API。
- `replay_engine.py`：逐行动重算有效精度、认知来源和纠正关系，并纳入规范快照。
- `model.py`：继续只处理意图和已提交事实叙事，不决定观察真假、记忆精度或纠正对象。
- `app.js`：展示玩家可见精度、纠正状态和固定公开文本，继续使用 `textContent`。

## 7. C01 固定内容链

### 7.1 新档初始认知

方笙在 `game_started` 边界获得两组固定认知：

1. 旧排班观察及来源记忆，支持既有 `fang_sheng:old_shift_schedule`。
2. “邵谦凭证最后登录”的观察及来源记忆，随后形成一个个人过度推断：“当晚只有邵谦使用凭证”。

第二组只是方笙的个人解释，`fact_id=NULL`，不是权威世界事件，也不证明邵谦实施了任何行为。初始观察的 `observed_at=0`，新档基础精度为 `exact`。

旧档迁移不补造这些初始记录。

### 7.2 询问委托细节：诚实误判

既有 `commission_details` 不消耗游戏内时间。除原有身份验证和自动短讯证词外，按当前记忆精度生成固定表达：

- `exact／vague`：方笙说明自己根据最后登录产生的怀疑；文本明确是“我记得／我怀疑”，不是系统旁白定论。
- `fragmentary／unknown`：不生成该独占使用推断，只保留原有委托细节。
- 证词引用方笙个人推断记忆，保存发言时精度，`accuracy='honest'` 且 `fact_id=NULL`。

该证词不授予线索、行动权限、Clock 或结局条件。

### 7.3 正常补充排班：分享并纠正

按“接受委托→询问委托细节→安抚方笙→前往新栖公寓→查看方笙住处”执行，最终行动后时间为 3：

1. 旧排班记忆仍为 `exact`，正常选择 `share_schedule`。
2. 产生既有共享账户补充证词，文本和机械权限不变。
3. 方笙重新整理旧排班后追加记忆纠正：最后登录不足以证明当晚只有邵谦使用凭证。
4. 若玩家此前收到对应误判证词，同时追加公开纠正证词，并引用该公开证词；否则只追加内部记忆纠正。
5. 远程场景仍使用 `fangsheng_remote_schedule`，可追加固定公开纠正提示，不新增场景机械效果。

纠正不证明“当晚另有指定人物”，只撤回过度推断。

### 7.4 延迟链：安全降级

在到期前额外消耗游戏内时间：

- 到期时为 `vague`：`share_schedule` 不再合法，`share_safe_reminder` 可给出不含独占推断的谨慎提醒，不追加精确纠正。
- 到期时为 `fragmentary`：两个分享候选均不合法，选择 `wait`，计划保持 pending，不产生证词或纠正。
- 无合法场景仍沿用第五阶段空操作；玩家主行动可以独立提交，NPC 子流程不写部分结果。

最低精度只影响非核心补充内容，不影响核心线索和三种结局。

## 8. 行动顺序、事务与并发

### 8.1 固定执行顺序

1. 完成现有玩家候选过滤、声明、权限审核和必要的公开 2D6。
2. 计算玩家主案件结果及行动后 `world_time`。
3. 按固定感知声明，在决策副本生成当前行动直接产生的观察和记忆。
4. 计算相关 holder 的有效精度，生成来源明确的证词或追加纠正。
5. 执行回应者判断及社会变化，再处理行动前已存在的到期计划。
6. NPC 按自身有效知识视图评分、试算并选择候选，导演只选择合法场景。
7. 合并最终认知、社会、计划和场景变化，再次校验来源、纠正目标和数量上限。
8. 生成版本 3 审计，进入唯一 `commit_action`。
9. 在同一 `BEGIN IMMEDIATE` 事务复核 revision、随机序号和行动前决策上下文哈希。
10. 写入既有事件、认知记录和全部机械状态；叙事仍在机械提交后执行。

行动前上下文哈希覆盖已有认知记录，但不包含本行动尚未提交的新记录；新记录必须由保存的行动、意图、骰点和固定内容确定生成。

### 8.2 有界执行

- 单行动最多生成 32 条认知记录、8 条追加纠正；当前 C01 实际数量远低于上限。
- 单 holder 来源图遍历最多 64 个节点，发现环、重复主键或跨档引用立即报错。
- 每行动最多 8 个到期计划、每计划最多 8 个候选、导演最多 16 个场景，沿用第五阶段上限。
- 不在同一行动递归触发“纠正→新观察→再纠正”；本阶段生成的新认知只供当前声明和后续行动使用。

### 8.3 事务与异常

- 任一来源、精度、纠正或事件写入失败，玩家行动、NPC 决策和全部领域状态整体回滚。
- 认知上下文被外部修改时，沿用 `StateConflict('决策上下文已变化，请重新预览')`。
- 请求幂等重试先读取既有结果，不重新生成认知 ID、记忆或纠正。
- 叙事失败只重试叙事，不重新衰减、生成证词或追加纠正。

## 9. 审计、API 与前端

### 9.1 内部审计 v3

`audit_json` 增加 `cognition`：

```json
{
  "world_time": 3,
  "records": [
    {
      "knowledge_id": "固定生成的记录 ID",
      "holder_id": "fang_sheng",
      "kind": "testimony",
      "source_record_id": "来源记忆 ID",
      "observed_at": null,
      "precision": "exact",
      "corrects_record_id": "先前公开误判证词 ID",
      "reason_codes": ["old_schedule_rechecked", "overgeneralization_retracted"]
    }
  ],
  "decay": [
    {
      "holder_id": "fang_sheng",
      "knowledge_id": "旧排班记忆 ID",
      "base_precision": "exact",
      "effective_precision": "exact",
      "elapsed_time": 3
    }
  ]
}
```

审计保存内部来源和理由，不保存任何由调用方自由提交的新事实效果。

### 9.2 玩家 API 裁剪

沿用 `GET /api/games/{game_id}/knowledge` 与行动审计 API：

- 玩家可见记录可返回 `knowledge_id`、`kind`、`accuracy`、`precision` 和公开纠正状态。
- 只有来源与目标都为玩家可见时，才返回对应公开引用；私有 NPC 记忆 ID、正文和来源链不得下发。
- 公开纠正可显示“该证词已有后续纠正”，但不暴露私有记忆纠正。
- 决策审计继续只返回最终候选和公开理由，不返回精确来源图、私密记忆或候选评分。
- 不新增全知认知查询、直接纠正或认知写入 API。

### 9.3 前端

- “观察与证词”增加“清晰／模糊／破碎／精度未知”和“已有纠正”固定标签。
- 公开纠正使用固定 `presentation_key`，说明原推断被撤回，不用模型临时改写历史。
- 行动审计增加“认知与纠正”区域，只显示玩家可见证词及纠正关系。
- 时间线沿用现有行动、叙事和场景事件，不新增空认知事件；源事件仍为产生这些记录的既有固定事件。
- 刷新只重建视图，不执行衰减写入或纠正。

## 10. 回放与版本兼容

1. SQLite schema 升级为 v6；`RULES_VERSION='action-pipeline-1.3'`，`CONTENT_VERSION='c01-1.3'`，新审计为 v3。
2. v5→v6 沿用现有备份和事务迁移方式，磁盘数据库保持 WAL、`synchronous=NORMAL`；真实迁移不属本阶段自动验收操作。
3. 旧记录的 `source_record_id`、`observed_at`、`corrects_record_id` 均为 `NULL`，`precision='unknown'`；不伪造来源、观察时间、精度或纠正。
4. 旧档可读取历史并继续新行动；无来源旧知识按 `unknown` 参与安全判断，不能满足任何最低精度候选，也不享受新档精确初始记忆。
5. `action-pipeline-1.2／c01-1.2` 及更早行动在 1.3 回放中返回 `status='unavailable'`、`reason.code='unsupported_version'`，公开历史仍可查看。
6. 回放只使用保存命令、意图和骰点，在独立内存 SQLite 重算观察、有效精度、证词、纠正和 NPC 选择，不调用模型或生成随机数。
7. 规范快照增加 `source_record_id`、`observed_at`、`precision`、`corrects_record_id`，并按行动边界核对公开证词的发言时精度。
8. 来源错接、精度篡改、纠正目标改变、旧证词正文被改写或纠正顺序变化，即使案件线索相同也返回 `mismatched`。
9. 私密认知差异继续只返回 `redacted`，完整内部来源不作为玩家差异输出。

## 11. 异常与安全回退

- 缺失来源、跨 holder 来源、跨档纠正、自指或来源环：配置／数据错误，整个真实行动回滚。
- 记忆时间缺失：旧迁移记录按 `unknown`；本版本新记录缺失则报错。
- 记忆精度不足：候选排除并记录内部理由，不自动生成事实或改用玩家知识。
- 误判没有公开目标：只执行合法内部纠正，不创建空公开纠正或伪造玩家历史。
- 纠正内容试图新增 `fact_id`、核心线索、行动权限或结局：拒绝并回滚。
- 数量或遍历超过上限：明确报错，不静默截断。
- 无合法候选或场景：沿用第五阶段安全空操作，玩家主行动可独立提交。
- 预览、刷新、假设 CRUD、现实等待和叙事重试不触发认知写入。

## 12. 先行测试与完成标准

### 12.1 来源、误判与精度

1. 新档初始观察和记忆来源完整；方笙不能读取其他 holder 私密记录或玩家假设。
2. 0／3／4／6／7 点时间边界返回预期有效精度，原记录和数据库哈希不变。
3. 诚实误判证词不生成 `case_facts`、核心线索、权限或 Clock。
4. `accuracy='honest'` 与内容正确性分离，`precision` 不被解释为真实性证明。
5. 证词保存发言时精度，源记忆之后衰减不改变旧证词。
6. 缺失来源、跨 holder、跨档、自指、成环和未来观察时间均拒绝。

### 12.2 C01 链与自主决策

7. 正常询问链产生误判证词，世界时间 3 仍选择 `share_schedule` 并追加公开纠正。

9. `vague` 选择谨慎提醒，`fragmentary` 等待；无合法场景不写 NPC 子流程状态。
10. 高分候选不能绕过最低精度、回应者、固定感知或纠正权限。
11. 误判与纠正不新增核心线索、行动权限或改变三种结局。

### 12.3 事务、迁移与回放

12. 认知记录、来源事件、计划和场景共享一次事务；故障注入覆盖来源、证词和纠正写入失败。
13. 决策上下文变化返回 409；幂等重试不重复认知记录或消耗随机序号。
14. v5 临时旧档备份迁移后字段为 unknown／空，历史可读，不补造初始误判。
15. 内部审计保留来源与精度，公开 API 不泄露私有记忆和来源图。
16. 新档最新与前缀回放一致；来源、精度和纠正篡改返回 mismatched。
17. 旧版本返回 unsupported_version；预览、假设 CRUD、刷新和叙事重试无认知副作用。
